# Comment Hygiene v1.0.0

## Objective

Provide a small, syntax-aware workflow for reviewing and intentionally removing
low-value source-code comments without treating comment-like string contents as
comments.

This is a retrospective specification: the core behavior existed before Taskrail
was adopted. Its acceptance criteria are verified against the current repository,
not claimed as contemporaneous release evidence.

## AST-safe candidate detection

- The workflow uses pinned `uncomment` 3.7.0 behavior to identify comment nodes.
- `audit` previews ordinary comment candidates without modifying input files.
- `audit-all` broadens the preview to documentation, TODO, and FIXME comments.
- String data that resembles comments remains outside the candidate set.
- Recognized tool directives and `~keep`-protected comments follow `uncomment`'s
  preservation behavior.

## Intentional comment removal

- `strip` removes ordinary comments only after explicit apply confirmation.
- `strip-all` additionally targets documentation, TODO, and FIXME comments.
- Direct mutating wrapper calls without `--apply` fail before changing files.
- The public Task targets make mutating behavior clear in their names and help.

## Agent review workflow

- A portable `comment-hygiene` skill instructs agents to inspect candidates in
  context rather than deleting them mechanically.
- The skill limits default review scope to files changed by the current task.
- It preserves comments carrying non-obvious intent, constraints, rationale,
  compatibility requirements, or security information.
- It does not claim measured effects on model quality or hallucinations.

## Reproducible project checks

- Mise pins the required toolchain and repository utilities.
- The behavioral test runs the real wrapper and `uncomment` binary against a
  representative Python fixture.
- The test proves that ordinary comments are removed while URL-like string data
  and a TODO comment remain.
- `mise run check` validates shell syntax, repository policy, Taskrail state, and
  the behavioral fixture.

## Repository workflow

- The README explains the purpose, safety model, setup, commands, limitations,
  development workflow, and roadmap for a human GitHub audience.
- Lefthook provides opt-in pre-commit, commit-message, and pre-push checks adapted
  from Taskrail's repository workflow.
- Taskrail 0.4.0 tracks specifications and follow-up tasks in committed files.
- CI runs the pinned repository check on pull requests and pushes to `main`.

## Acceptance criteria

1. `mise run test` passes using the real pinned `uncomment` CLI.
2. A direct strip invocation without `--apply` fails and leaves its input intact.
3. `mise run check` passes from a clean checkout after setup.
4. Taskrail validates the v1.0 and v1.2 specifications and their task references.
5. Public files contain no source-repository name, and reachable commit messages
   contain no session URL or session identifier.

## Explicitly out of scope

- LLM-based comment classification or rewriting.
- Automatic deletion without human or agent review.
- Package-manager installation for agent-skill ecosystems.
- Exhaustive testing of every language supported by `uncomment`.
